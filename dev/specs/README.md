# Feature specs

Create one Markdown file per initiative:

```
specs/<domain>-<short-name>.md
```

Examples:

- `specs/finance-giving-ui.md`
- `specs/branches-crud-api.md`
- `specs/documents-upload-flow.md`

Start from **[`_TEMPLATE.md`](./_TEMPLATE.md)** so scope, APIs, and acceptance criteria stay consistent.

When implementation merges, either archive the spec under `specs/done/` (optional) or link it from git history—avoid deleting useful requirements history without backup.
